What each production release of Lasso Cloud adds, with a link to the page that
explains it. To check what's serving right now, read `source_sha` from
[`/api/health`](https://lasso.sh/api/health). RPC Core releases have their own
notes on [GitHub](https://github.com/jaxernst/lasso-rpc/releases).

<Update label="November 22, 2026" description="Release 324" tags={["Routing", "Custom profiles", "Dashboard", "Reliability"]}>

- **Balanced-fast is the default everywhere but Public.** A URL with no
  strategy segment now routes `balanced-fast` on Custom profiles too, not only
  Premium; a pinned provider and Public still use `load-balanced`.
  [Routing](/cloud/routing)
- **Provider lag shows by time, not blocks.** The dashboard marks a provider
  **Lagging** once it trails the chain's reference head by more than 10
  seconds, converted to blocks at the chain's measured cadence, so a fast
  chain like Base doesn't trip the warning early.
  [Custom profiles](/cloud/custom-profiles#head-tracking)
- Routing, historical-read and `eth_getLogs` reliability improvements.

</Update>

<Update label="November 21, 2026, second release" description="Release 323" tags={["Pricing", "Custom profiles", "Keys", "Routing"]}>

- **Lower prices for faster routing.** `balanced-fast` now costs 1.25x a
  load-balanced request, down from 1.5x, and `fastest` costs 1.75x, down from
  2x. Load-balanced and priority stay at 1x. An `eth_call` on `balanced-fast`
  is $0.00001875, and on `fastest` $0.00002625.
  [Pricing](/cloud/serving-access-and-pricing)
- **WebSocket URLs for Custom providers.** Set or change a provider's
  WebSocket URL while you draft a Custom profile. Paste a WebSocket URL and it
  attaches to its provider; a key for a supported vendor also fills in that
  vendor's WebSocket URL. Before a socket goes live, Lasso checks that it
  serves the provider's chain. If it doesn't, the provider runs on HTTP and
  its panel says the socket is unused.
- **Provider credentials stay on their origin.** A provider's headers go to
  its WebSocket only when the socket shares the HTTP URL's host and port. For
  a socket on another host, put its credentials in the socket URL.
- **Keys on provider-pinned URLs.** Provider-pinned URLs take your key as a
  path segment too: `/rpc/k/<key>/provider/<id>/<chain>`, and the same under a
  profile. A 401 names the three ways to send a key: a `/k/<key>` path
  segment, a `key=` parameter or an `x-lasso-api-key` header.
- **Hung providers leave rotation.** When a request to a provider times out,
  Lasso probes that provider on its own budget. A provider that accepts
  connections but never answers fails those probes, its circuit opens, and
  traffic moves to healthy routes.
- **Smarter fastest and latest reads.**
  - `fastest` tries routes with recent failures last.
  - Latest reads judge a provider's lag against how old its last head report
    is, so a provider that is always behind stays out of latest reads.

</Update>

<Update label="November 19, 2026" description="Release 320" tags={["Custom profiles", "Dashboard", "Privacy", "Performance"]}>

- **A clearer Custom profile overview.** Each chain endpoint gets one row,
  and the row opens that chain's details, with its key, strategies and copy
  buttons in one place. In edit mode, each chain shows whether it's ready to
  route, and **Reorder** sets provider priority with arrows. A deep check
  shows its progress and ends with a coverage summary per chain: throughput,
  history and log range. A retest that finds nothing new says
  **No changes detected** and stages nothing.
  [Custom profiles](/cloud/custom-profiles#the-dashboard-edit-view)
- **Set up more of a profile before you sign in.** On a new Custom profile you
  can reorder providers and set each one's **Enabled**,
  **Historical requests**, **Subscribe to new heads** and **Max logs range**
  before signing in. The new-profile screen links Chainlist for public
  fallback URLs and points to where provider keys come from.
- **Use public RPC from the home page.** The lasso.sh home page button that
  opens the live public dashboard now reads **Use public RPC**.
- **Dashboards stay responsive with many tabs open.** Provider updates that
  only refresh a timestamp no longer rebuild every open tab, and each tab
  pulls less data from other regions while you watch. Updates keep streaming
  at the same pace.
- **Error reports leave out your request.** When a request causes an error
  inside Lasso, the error report no longer includes the request body, any
  request headers or your IP address.
  [Data handling](/cloud/data-handling#request-contents)
- **Less work per block on busy chains.** Lasso spends less server work on
  each new block head, most on chains with many providers, which leaves more
  room for your requests.

</Update>

<Update label="November 18, 2026, second release" description="Release 319" tags={["Custom profiles", "Performance", "Routing", "Dashboard"]}>

- **Custom profile changes route as soon as they publish.** When you replace
  providers, the new set takes over right away and each new provider starts
  serving once its address resolves, retried about once a second. While a
  chain has no connectable provider yet, its reads return a retryable `-32000`
  with reason `admission_unavailable`, and other chains and profiles keep
  serving.
  [Custom profiles](/cloud/custom-profiles#onboarding-what-lasso-checks)
- **Faster profile saves and reads.** A save returns once your document is
  stored, and Lasso publishes it in the background; read
  `GET /api/v1/profiles/{slug}` until it reports `live`. Lasso checks up to
  eight provider URLs at once when you save, and profile reads take fewer
  steps.
- **Wide public log scans can't crowd out your other calls.** On the `public`
  profile, an `eth_getLogs` range wider than 10,000 blocks counts as bulk work
  from its first attempt and shares a separate allowance on each provider.
  Ranges of 10,000 blocks or fewer, and every other call, keep flowing while
  wide scans run.
  [Indexers and backfills](/cloud/indexer-backfills#limits)
- **Gateway method refusals read as capability errors.** When a provider's
  gateway turns a method away with an HTTP 406 page, Lasso returns it as a
  `-32002` capability error you can safely retry, and the refusal doesn't
  count against that provider's health.
- **The lag warning appears only when lag can slip past.** A polled provider's
  head stays usable for 1.5 poll intervals, so **Active monitoring** in the
  chain editor warns only when polls are slower than three times the chain's
  freshness window, or polling is off.
  [Head tracking](/cloud/custom-profiles#head-tracking)

</Update>

<Update label="November 18, 2026" description="Release 318" tags={["Routing", "Custom profiles", "Subscriptions", "Reliability"]}>

- **Reads go to providers at the chain head, with no lag setting to tune.**
  Lasso ranks providers it knows are behind after those at the head. Receipt
  and transaction lookups by hash, and calls that leave out the block
  parameter, such as `eth_call` and `eth_estimateGas`, follow the same rule,
  so a lookup for a transaction that just landed reaches a provider that has
  it. A provider that's behind still serves when it's the only one that can.
  The `max_lag_blocks` setting is retired: Custom profiles drop it when you
  save, so existing documents keep working.
  [Current reads](/cloud/rpc-behavior#current-reads)
- **getLogs errors size your next request from evidence.** When a range is too
  wide, `error.data.max_block_range` is the largest range Lasso has evidence
  it can serve: the part of your request it already served, or one slice of a
  provider's known limit. When no smaller range would fit, the error carries
  `data.action: "narrow_filter"`; narrow the address or topics filter instead.
  Retryable `-32005` advice comes only when the same request can fit on retry.
  [Range errors](/cloud/guides/getlogs-rate-limits-pay-with-x402)
- **Subscriptions recover through any healthy provider.** When a WebSocket
  subscription's provider drops, Lasso fills the missed blocks from a provider
  other than the replacement when one is available, so a slow replacement
  can't hold up recovery. If the replacement also drops while filling the gap,
  recovery moves on to the next provider within the same 30-second deadline.
  [WebSocket subscriptions](/cloud/rpc-behavior#websocket-subscriptions)
- **Rate-limited providers get the pause they ask for.** When a provider
  answers HTTP 429 with a retry time in its JSON-RPC body, Lasso rests it for
  that long, up to 10 minutes, including when the 429 answers Lasso's own head
  tracking. Your requests go to other providers in the meantime. Lasso's
  method checks stop as soon as a provider says its quota is spent.
  [Rate limits and failover](/cloud/guides/rpc-outages-and-rate-limits)
- **A new home page at lasso.sh.** Start from one of two buttons:
  **Bring your own providers** opens a new Custom profile, and
  **Explore public RPC** opens the live dashboard for the public profile.
  **Use with your agent** copies a setup prompt for your agent, and on wide
  screens an index beside the page shows where you are.

</Update>

<Update label="November 17, 2026" description="Release 317" tags={["Custom profiles", "Dashboard", "Reliability"]}>

- **Your Custom endpoint routes to your providers from its first request.**
  Activate now finishes once Lasso is serving the profile, so the URL you copy
  goes straight to your providers. If serving takes longer than a few seconds,
  the dashboard says **Profile activated. Publication is still finishing.**
  When your free Custom days are used, the footer says so before
  **Subscribe & activate** opens Checkout.
  [Custom profiles](/cloud/custom-profiles#onboarding-what-lasso-checks)
- **A provider that returns no usable block stays out of routing.** If a light
  check reads an empty or malformed latest block, Lasso withholds that
  provider whether you activate from the dashboard or the API. Run the light
  check again once the endpoint recovers and it routes again.
  [Provider checks](/cloud/custom-profiles#onboarding-what-lasso-checks)
- **One overloaded subscription no longer disrupts the rest.** When a
  WebSocket subscription can't keep up, Lasso closes only that client's
  connection, with code 1011, while other clients' subscriptions and pending
  RPC responses keep flowing. Reconnect and resubscribe the affected client.
  [WebSocket subscriptions](/cloud/rpc-behavior#websocket-subscriptions)
- **Requests fail over when a provider refuses your key.** Some providers
  answer a bad or expired key with HTTP 401 or 403 and a body that looks like
  an invalid request. Lasso now reads the status, sends the request to another
  eligible provider and counts the refusal against that provider's health.
  [Rate limits and failover](/cloud/guides/rpc-outages-and-rate-limits)

</Update>

<Update label="October 3–8, 2026" description="Releases 258–265: accounts for people and agents" tags={["Accounts", "Payments", "API"]}>

Lasso Cloud moved to accounts on October 7. Your existing RPC URLs and keys kept
working through the change.

### Accounts for people and agents

- **One account holds your keys, profiles and balance.** People and agents work
  on it as members, each with their own credential and permissions, and the
  dashboard shows its balance, subscriptions and usage per key.
  [Accounts, people and agents](/cloud/accounts-and-agents)
- **An agent can set up Lasso without a signup.** One unauthenticated
  `POST /api/v1/keys` creates an account with its agent, a first key and a
  $0.025 starting balance, and returns its RPC URL.
  [Quickstart](/cloud/quickstart)
- **Hand an agent's setup to a person.** The agent requests a single-use claim
  link. Claiming keeps it as a new account or merges it into one you already
  have, with a preview of the combined balance, keys, rate limits and agents
  before you confirm. Every key and URL keeps working.
  [Accounts, people and agents](/cloud/accounts-and-agents)
- **Bring an agent into an existing account.** The agent asks to connect and
  gets an approval link; once an admin approves, it works on that account.
  [Accounts, people and agents](/cloud/accounts-and-agents)
- **Rotate a key with no downtime.** The old secret keeps serving for the grace
  period you choose, so each deploy switches over in its own time.
  [Rotate a key](/cloud/guides/rotate-a-key)

### One balance, priced per method

- **One USD balance per account.** Every request is priced by method and
  strategy, and each response tells you what it cost in `x-lasso-cu` and
  `x-lasso-usd`. [Chains and prices](/cloud/reference/chains-and-prices)
- **Top up with a stablecoin wallet, no Lasso credential needed.** Credit
  requests answer with a standard 402 challenge for x402 (USDC on Base) or MPP
  (USDC.e on Tempo); any stock client can pay it.
  [Balance and payment fallback](/cloud/balance-and-fallback)
- **Your app keeps serving when the money runs out.** An account that has paid
  before falls back to public providers for 30 days while you top up, marked
  with `x-lasso-fallback: payment`.
  [Balance and payment fallback](/cloud/balance-and-fallback)
- **Free access, Pro and Custom are account subscriptions.** Included usage is
  counted in CU per month, and usage beyond it draws on the balance.
  [Serving access and pricing](/cloud/serving-access-and-pricing)

### API and signals

- **The account API lives at `/api/v1`**, described in full by
  [`openapi.json`](https://lasso.sh/openapi.json). Agent API v2 RPC URLs keep
  working.
- **WebSocket RPC on every key**, including keys an agent creates.
  [Keys and profiles](/cloud/keys-and-profiles)
- **Every response explains itself.** `x-lasso-request-id`, `x-lasso-access`,
  `x-lasso-balance-usd` and the `RateLimit` headers show who served the request,
  what it cost and how much room is left. Errors that Lasso originates carry a
  `code` and a `next_action`, listed in one reference.
  [Signals and errors](/cloud/reference/signals-and-errors)

### Changes to note

- An RPC key can no longer request a claim link for an account an agent
  created; the agent requests it. Accounts migrated from keys that predate
  agents still claim with their key.
  [Accounts, people and agents](/cloud/accounts-and-agents)
- Keys an agent creates share their account's rate limit instead of each
  getting 50 RPS. [Serving access and pricing](/cloud/serving-access-and-pricing#rate-limits)
- Free access is counted in per-method CU instead of bytes.
  [Serving access and pricing](/cloud/serving-access-and-pricing)

</Update>
