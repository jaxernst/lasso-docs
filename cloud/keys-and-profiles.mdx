# Keys, URLs and profiles

One RPC key, saved once in `.env`, reaches every profile its account has:
Lasso's `premium` and `public` pools and each of your Custom profiles. The URL,
not a key setting, picks the profile, the strategy and the chain. Use this page
to build URLs and scope keys you have to expose.

```bash
# .env: the key, which reaches every pool
LASSO_KEY=lasso_…
```

```ts
const base   = `https://lasso.sh/rpc/k/${process.env.LASSO_KEY}`;
const reads  = `${base}/profile/premium/balanced-fast/base`;  // Lasso's premium providers
const jobs   = `${base}/profile/public/base`;                 // Lasso's public providers, uncharged
const trades = `${base}/profile/prod-base/fastest/base`;      // your own providers
```

## URL grammar

```text
<base>[/profile/<profile>][/<strategy>]/<chain>
```

| Base | Form |
|---|---|
| `https://lasso.sh/rpc/k/<key>` | HTTP, key in the path (`rpc_url`) |
| `wss://lasso.sh/ws/rpc/k/<key>` | WebSocket, key in the path (`ws_url`) |
| `https://lasso.sh/rpc` | HTTP, key in `Authorization: Bearer <key>` or `x-lasso-api-key` |
| `wss://lasso.sh/ws/rpc` | WebSocket, key in `Authorization: Bearer <key>` or `x-lasso-api-key` |

- `<chain>` is a chain name or decimal chain ID from
  [chains and prices](/cloud/reference/chains-and-prices).
- `<strategy>` is optional; `balanced-fast` is the default on Premium and
  `load-balanced` elsewhere. See
  [routing](/cloud/routing).
- `<profile>` is `premium`, `public` or one of your Custom profile slugs.
  A URL without a profile segment is served by `premium`.
- `<base>[/profile/<profile>]/provider/<name>/<chain>` pins one provider for
  debugging. Managed providers use their public aliases.

Creating or rotating an unrestricted key returns `rpc_url` and `ws_url` ending
in `/profile/premium`; a scoped key's URLs end in an allowed profile. Append a
strategy and a chain. To use another profile, replace that segment rather than
adding a second one.

## Scope a key

`allowed_profiles` sets which profiles a key can name in its URL. It defaults
to `all`: every current and future profile of the account. Scope any key whose
URL ships to a browser or mobile app to `public`, so a copied key can't spend
the balance:

```http
POST https://lasso.sh/api/v1/keys
Authorization: Bearer <management token>
Content-Type: application/json

{"name": "jobs", "allowed_profiles": ["public"]}
```

Its `rpc_url` ends in `/profile/public`. A scoped key that names another
profile, or a URL without a profile segment when `premium` isn't allowed, gets
`forbidden`, listing what it can use. A key scoped to a Custom profile isn't
safe to expose: if Custom access lapses, it's served and charged as `premium`.
`PATCH /api/v1/keys/{id}` changes a key's scope.

## How a profile segment resolves

| The URL names | Result |
|---|---|
| Nothing | `premium` |
| A profile the key is allowed | That profile |
| A profile outside a scoped key's allowed set | 403 `forbidden`, naming the allowed profiles |
| A slug the account has never had | 404 `unknown_profile`, listing the account's profiles |
| A Custom profile that was deleted, or whose Custom access lapsed | Served as `premium`, with `x-lasso-fallback: profile` |

Whether `premium` is served by premium providers depends on the account's
payment state, not the URL. See
[serving access and pricing](/cloud/serving-access-and-pricing).

## Rotate and revoke

`POST /api/v1/keys/{id}/rotate` issues a new secret and keeps the old one
working for an overlap you choose, so deploys catch up with no downtime; see
[rotate a key](/cloud/guides/rotate-a-key). `DELETE /api/v1/keys/{id}` revokes
a key. Every URL Lasso has issued keeps serving; older URL forms are on
[upgrading from Agent API v2](/cloud/reference/v2-compatibility).

## Limits

- The API returns a key's secret only on create and rotate. If you lose it,
  rotate the key or create another; admins can view active keys' URLs in the
  dashboard.
- An account holds at most 100 active keys.
- `premium` and `public` are reserved; Custom profile slugs can't use them.
