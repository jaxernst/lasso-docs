# Quickstart

Create a working Lasso endpoint, call it, and put it in your app. Agents can do
all of it over HTTP with no signup; people can do the same in the dashboard.
Both paths end in the same place: an account with one key whose URL your app
keeps in `.env`.

## With an agent, through the API

### 1. Create an endpoint

```bash
curl -sS https://lasso.sh/api/v1/keys \
  -H 'content-type: application/json' -d '{"name":"prod"}'
```

```json
{
  "id": "…",
  "key": "lasso_…",
  "rpc_url": "https://lasso.sh/rpc/k/lasso_…/profile/premium",
  "ws_url": "wss://lasso.sh/ws/rpc/k/lasso_…/profile/premium",
  "account_id": "…",
  "management_token": "lasso_mk_…"
}
```

A `201` with `serving_ready: true` means the key is ready. A `202` with
`serving_ready: false` returns the committed credentials: save them, wait
`Retry-After`, then call RPC. For `service_initializing`, wait and retry RPC
with the same key; do not repeat creation.

That one request creates a provisional account with a starting balance
(`pricing.free_grant_usd` in [`agent.json`](https://lasso.sh/agent.json),
enough to verify but not to run production) and issues your first key. The
key is all you need to call, read the account and top it up.
`management_token` makes you the account's agent, for when you later add keys,
build Custom profiles or hand the account to a person.

### 2. Call it

Append a chain, and optionally a strategy, to `rpc_url`:

```bash
curl -fsS --retry 5 "$LASSO_RPC_URL/fastest/base?include_meta=body" \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}'
```

```json
{
  "jsonrpc": "2.0", "id": 1, "result": "0x3157d37",
  "lasso_meta": {
    "strategy": "fastest", "chain_id": 8453,
    "selected_provider": { "id": "premium_base_2", "protocol": "http" },
    "upstream_latency_ms": 9.4, "lasso_overhead_ms": 1.9, "retries": 0
  }
}
```

`--retry` repeats the errors Lasso marks retryable (HTTP 503 or 429); fix
anything else. Every response also carries `x-lasso-request-id`,
`x-lasso-access` (`premium`, `public` or `custom`), `x-lasso-usd` (what it
cost) and `x-lasso-balance-usd` (an estimate of the balance after it). Use
`eth_blockNumber` rather than `eth_chainId` to see routing, since the chain ID
can be answered without an upstream.

### 3. Pick a pool and a strategy per call site

The same key reaches every profile of its account, and the URL picks one.
`rpc_url` ends in `/profile/premium`; to switch pools, replace that segment
rather than adding another:

| URL | Served by |
|---|---|
| `$LASSO_RPC_URL/fastest/base` | `premium` |
| `https://lasso.sh/rpc/k/<key>/profile/public/base` | Lasso's public providers, uncharged while the account has spending power, `load-balanced` |
| `https://lasso.sh/rpc/k/<key>/profile/prod-base/fastest/base` | Your `prod-base` Custom profile |

| Strategy | What it does | Use it for |
|---|---|---|
| `load-balanced` | Spreads requests in random order across healthy providers | Backends, indexers |
| `balanced-fast` (default on Premium) | Random order weighted toward providers with lower recent latency | User-facing reads |
| `fastest` | Tries the provider with the lowest recent latency for this kind of request first | Trading and other latency-critical paths |
| `priority` | Tries providers in your Custom profile's configured order | A preferred primary with backups |

Strategies price differently on premium; the live table is in
[chains and prices](/cloud/reference/chains-and-prices).

### 4. Install it

Save the key once in `.env` and build every URL from it:

```bash
# .env
LASSO_RPC_URL=https://lasso.sh/rpc/k/lasso_…/profile/premium
LASSO_WS_URL=wss://lasso.sh/ws/rpc/k/lasso_…/profile/premium
```

```ts
import { createPublicClient, http } from "viem";
import { base } from "viem/chains";

const client = createPublicClient({
  chain: base,
  transport: http(`${process.env.LASSO_RPC_URL}/balanced-fast/base`),
});
```

The same URL works in ethers, Foundry (`--rpc-url`), Hardhat and indexers. For
subscriptions, use `${LASSO_WS_URL}/base` with a WebSocket transport. Run your
app's real methods and block ranges through the new URL before moving traffic.
[Install Lasso in your app](/cloud/install) covers each client.

### 5. Fund it

When the starting balance isn't enough, look up the account with the key, then
credit it within the budget your user approved:

```bash
curl -sS https://lasso.sh/api/v1/accounts/current \
  -H "authorization: Bearer <RPC key>" | jq '{id, balance_usd}'
```

```http
POST https://lasso.sh/api/v1/accounts/{id}/credit
Content-Type: application/json

{"usd":"1"}
```

The credit answers 402 with a standard x402 or MPP challenge that a stock
client signs with the user's wallet, within the per-purchase range
(`minimum_usd` to `maximum_usd` in `account_payments.rails`)
([example](/cloud/balance-and-fallback#top-up)).

To add keys per environment or hand the account to its owner, see
[set up production RPC with an agent](/cloud/guides/production-rpc-with-an-agent).

## Start with a funded key

If you already have an authorized payment wallet, buy the endpoint and its
starting balance together. Use the fixed URL before creating a free key:

```http
POST https://lasso.sh/api/v1/credit
Content-Type: application/json

{"usd":"5"}
```

The first request answers 402. Sign one offered x402 or MPP challenge within
your budget, then repeat the same request with that payment. `200` confirms
the credit; `202` means settlement is pending, so poll `status_url` and never
pay twice. The response that creates the account returns its credentials once
under `key`, including `rpc_url`, `ws_url`, `key`, `management_token` and
`account_id`. Save them privately even if that response reports payment failure.
A replay returns the purchase without credentials. Top up the saved account
with the account credit route rather than creating another funded key.
See [funded keys](/cloud/balance-and-fallback#buy-a-funded-key).

## With the dashboard

1. Sign in at [lasso.sh](https://lasso.sh).
2. Create an endpoint. Your first endpoint creates your account, and you're
   its admin.
3. Copy its RPC URL into your app's `.env`. Requests are served on public
   providers under your free monthly allowance, and the dashboard says so.
4. Add balance, or subscribe to Pro, and the next request is served by premium
   providers. Subscribe to Custom to route over your own providers.

## Limits

- Creating accounts without credentials is limited to 10 per hour per client
  IP. Each provisional account gets its starting balance once.
- A provisional account that never pays and sees no activity for 90 days
  closes. Accounts that have paid, or that a person has joined, never expire.
- Paying always needs a wallet signature; no Lasso credential can spend
  money.
- `public` serves `load-balanced` only. A different strategy in a `public` URL
  is served as `load-balanced`, and `lasso_meta.strategy` says so.
