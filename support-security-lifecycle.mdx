# Support, security and lifecycle

Use the channel that matches the problem. Support runs through the public
channels below; response-time and uptime commitments come only with a separate
written agreement.

## Get help or report a problem

| Need | Where | Include |
| --- | --- | --- |
| Lasso Cloud question, bug or incident | `POST https://lasso.sh/api/v1/feedback` (no credential needed), or a [documentation issue](https://github.com/jaxernst/lasso-docs/issues/new) | UTC time, route shape without the key, chain, method, response code and `x-lasso-request-id` |
| RPC Core bug or feature request | An [RPC Core issue](https://github.com/jaxernst/lasso-rpc/issues/new) | Core version, deployment shape, configuration with secrets removed, and steps to reproduce |
| Documentation problem | A [documentation issue](https://github.com/jaxernst/lasso-docs/issues/new) | Page URL and the text that's unclear or wrong |
| Security vulnerability | Private email, below | Affected surface, reproduction and likely impact |

Never post keys, cookies, provider URLs or credentials, billing details or
personal data in an issue. If a report needs sensitive evidence, open a
redacted issue and ask for a private channel.

For Cloud status, check the
[public status page](https://lasso-rpc-status.checkly-status-page.com/) and
[`/api/health`](https://lasso.sh/api/health). If your workload can't tolerate
an outage, keep a previous endpoint or a self-hosted deployment as a rollback.

## Report a security vulnerability

Email `jaxernst@gmail.com`; don't open a public issue. This is the same channel
as the [RPC Core security policy](https://github.com/jaxernst/lasso-rpc/security/policy).
Include enough detail to reproduce the problem, but no live production
credentials. Confirmed issues are fixed and disclosed on a timeline agreed with
the reporter.

To harden a self-hosted deployment, see the Core
[security considerations](https://github.com/jaxernst/lasso-rpc/blob/main/SECURITY.md#security-considerations-for-self-hosting)
and the [production checklist](/deployment/production-checklist).

## Versions and lifecycle

**RPC Core** fixes land in the latest published release; upgrade older
versions before requesting a fix. In production, run a versioned GitHub
release by its recorded container digest, and read each release's
compatibility notes before upgrading, since Core is pre-1.0. See
[versions and evidence](/releases-and-availability).

**Lasso Cloud** deploys continuously; [What's new](/cloud/whats-new) lists
each production release. Build automation against the live
[`openapi.json`](https://lasso.sh/openapi.json) and
[`agent.json`](https://lasso.sh/agent.json), which report what the deployed
service serves.
