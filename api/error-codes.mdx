---
title: Error Codes
description: JSON-RPC error codes and error handling in Lasso
---

Lasso validates JSON-RPC response envelopes and authors valid JSON-RPC errors
for failures it owns. A request-correlated upstream JSON-RPC error remains
authoritative: Lasso preserves its `code`, `message`, and optional `data`
instead of replacing provider semantics with a synthetic universal error.

## Error Response Format

All errors follow the JSON-RPC 2.0 specification:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32601,
    "message": "Method not supported over HTTP. Use WebSocket connection for subscriptions.",
    "data": {
      "websocket_url": "/ws/rpc/ethereum"
    }
  }
}
```

### Error Object Fields

| Field | Type | Description |
|-------|------|-------------|
| `code` | integer | Standard JSON-RPC error code or server-defined code |
| `message` | string | Human-readable error description |
| `data` | object (optional) | Additional error context and hints |

## Standard JSON-RPC Error Codes

Lasso implements the complete JSON-RPC 2.0 error code specification:

### -32700: Parse Error

**Meaning:** Invalid JSON was received by the server. The request could not be parsed.

**Common Causes:**
- Malformed JSON syntax
- Invalid UTF-8 encoding
- Truncated request body

**Example:**

```json
{
  "jsonrpc": "2.0",
  "id": null,
  "error": {
    "code": -32700,
    "message": "Parse error: Invalid JSON"
  }
}
```

### -32600: Invalid Request

**Meaning:** The JSON sent is not a valid Request object.

**Common Causes:**
- Missing required `method` field
- Invalid field types
- Batch request exceeds maximum size (default: 50)
- Invalid `jsonrpc` version (must be "2.0")

A valid request without `id` is a notification, not an invalid request. Lasso
does not send a JSON-RPC response to a valid notification.

**Examples:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32600,
    "message": "Invalid Request: Missing required field 'method'"
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32600,
    "message": "Invalid Request: Batch size 75 exceeds maximum of 50",
    "data": {
      "batch_size": 75,
      "max_batch_size": 50
    }
  }
}
```

### -32601: Method Not Found

**Meaning:** The requested method does not exist or is not supported in the current context.

**Common Causes:**
- Method name typo
- Subscription method called over HTTP (use WebSocket)
- Blocked node-local wallet or signing method
- Chain-specific method not available on requested chain

Core v0.4.4 can forward provider-local filter methods when capability policy
permits, with one dispatch per request and no cross-request upstream affinity.
Lasso Cloud rejects its documented filter lifecycle locally. See the separate
[Core method contract](/api/supported-methods#stateful-filters-and-extensions) and
[Cloud filter policy](/cloud/rpc-behavior#stateful-http-filters).

**Examples:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32601,
    "message": "Method not supported over HTTP. Use WebSocket connection for subscriptions.",
    "data": {
      "websocket_url": "/ws/rpc/ethereum",
      "hint": "Connect via WebSocket to use eth_subscribe"
    }
  }
}
```

<Info>
When subscription methods are called over HTTP, Lasso provides the correct WebSocket URL in the `data.websocket_url` field, mirroring the HTTP request path structure.
</Info>

### -32602: Invalid Params

**Meaning:** Invalid method parameter(s).

**Common Causes:**
- Unsupported chain name or ID
- Missing required parameters
- Invalid parameter types or formats
- Block number out of range

**Examples:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32602,
    "message": "Invalid params: Unsupported chain 'polygon'",
    "data": {
      "chain": "polygon",
      "supported_chains": ["ethereum", "base", "arbitrum"]
    }
  }
}
```

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32602,
    "message": "Invalid params: Block number must be a hex string or block tag",
    "data": {
      "provided": 12345,
      "expected": "0x3039 or 'latest', 'earliest', 'pending', 'safe', 'finalized'"
    }
  }
}
```

### -32603: Internal error

An internal JSON-RPC error. Do not classify every provider failure or routing
exhaustion as `-32603`; upstream errors retain their own semantics.

### Core routing exhaustion

Released Core v0.4.4 returns routing exhaustion as a JSON-RPC `-32000` error over
HTTP 200 and preserves the client's request ID. It does not publish
`attempted_providers` or `circuit_breaker_states` in the error payload.
Use opt-in [request metadata](/observability/request-metadata) for recorded
channel attempts where available.

The all-circuits-open case can include `retry_after_ms`. This generated serializer
example uses a fixed five-second retry interval; the actual interval depends on
the current circuit state:

```json
{
  "error": {
    "code": -32000,
    "data": {
      "retry_after_ms": 5000
    },
    "message": "No available channels for method: eth_blockNumber. All circuits open, retry after 5s"
  },
  "id": "client-request-42",
  "jsonrpc": "2.0"
}
```

The shape matches the released [controller regression](https://github.com/jaxernst/lasso-rpc/blob/v0.4.4/test/lasso_web/controllers/rpc_controller_test.exs)
and [error contract](https://github.com/jaxernst/lasso-rpc/blob/v0.4.4/docs/API_REFERENCE.md#error-responses).
Other exhaustion paths need not have this retry field or message.

### -32000: Server Error

**Meaning:** Server-side error specific to Lasso's operation.

<Note>
Core has no built-in incoming customer authentication or quota enforcement.
Access, billing and plan examples below are not a self-hosted Core contract;
consult [Cloud RPC behavior](/cloud/rpc-behavior) for managed-service boundaries.
</Note>

**Common Causes:**
- Rate limit exceeded
- Strategy access denied (profile restriction)
- Quota exceeded
- Provider override failed
- Authentication failure

**Examples:**

**Rate Limiting:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32000,
    "message": "Rate limit exceeded. Limit: 100 requests per second.",
    "data": {
      "retry_after_ms": 150,
      "rate_limit": 100,
      "current_usage": 105
    }
  }
}
```

<Tip>
When rate limited, use the `retry_after_ms` value in the error data to implement exponential backoff.
</Tip>

**Authentication Failure:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32000,
    "message": "Authentication failed: Invalid API key",
    "data": {
      "hint": "Provide API key via ?key=, X-Lasso-Api-Key header, or Authorization: Bearer"
    }
  }
}
```

**Quota Exceeded:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32000,
    "message": "Monthly quota exceeded",
    "data": {
      "quota_limit": 1000000,
      "usage": 1000042,
      "reset_date": "2026-04-01T00:00:00Z"
    }
  }
}
```

**Strategy Access Denied:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32000,
    "message": "Strategy 'fastest' not allowed for profile 'free'",
    "data": {
      "allowed_strategies": ["load_balanced"],
      "requested_strategy": "fastest"
    }
  }
}
```

## Batch Request Errors

When sending batch requests, each item in the response array contains either a `result` or `error` field:

**Request:**

```json
[
  {"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1},
  {"jsonrpc":"2.0","method":"eth_invalidMethod","params":[],"id":2},
  {"jsonrpc":"2.0","method":"eth_chainId","params":[],"id":3}
]
```

**Response:**

```json
[
  {
    "jsonrpc": "2.0",
    "id": 1,
    "result": "0x8471c9a"
  },
  {
    "jsonrpc": "2.0",
    "id": 2,
    "error": {
      "code": -32601,
      "message": "Method not found: eth_invalidMethod"
    }
  },
  {
    "jsonrpc": "2.0",
    "id": 3,
    "result": "0x1"
  }
]
```

## Provider-Specific Errors

Providers can return valid JSON-RPC errors with an HTTP 2xx, 4xx, or 5xx
status. Lasso preserves a structurally valid, request-correlated upstream error:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32005,
    "message": "query exceeds provider block range",
    "data": {"maxBlockRange": 10000}
  }
}
```

Lasso classifies capacity, capability, transport, and execution failures
internally so it can decide whether failover is safe. Those categories do not
replace the terminal provider error returned to the caller. Non-JSON bodies,
gateway pages, and malformed envelopes remain transport failures.

## WebSocket Errors

WebSocket connections may receive errors in the same JSON-RPC format. Additionally, the connection may be closed with a specific close code:

### WebSocket Close Codes

| Code | Meaning | Description |
|------|---------|-------------|
| 1000 | Normal Closure | Subscription completed successfully |
| 1001 | Going Away | Server shutting down |
| 1002 | Protocol Error | Invalid frame or message format |
| 1003 | Unsupported Data | Message type not supported |
| 1008 | Policy Violation | Authentication failed or rate limit exceeded |
| 1011 | Internal Error | Server error |

### Heartbeat Timeout

Lasso sends WebSocket pings every 30 seconds. If no pong is received within 5 seconds, the connection will be closed after 2 missed heartbeats:

```json
{
  "jsonrpc": "2.0",
  "id": null,
  "error": {
    "code": -32000,
    "message": "Connection timeout: No heartbeat response",
    "data": {
      "missed_heartbeats": 2,
      "timeout_ms": 5000
    }
  }
}
```

## Error Handling Best Practices

### Retry Strategy

An error code or `retry_after_ms` hint does not establish that a request is safe
to repeat. Core can fail over reviewed replay-safe reads within one request's
dispatch limit and absolute deadline. A new application request starts a new
execution envelope; bound any application retries and their total elapsed time.

Do not automatically replay signed transaction submissions, stateful filter
operations or unknown methods based on these error fields. A lost transaction
response may follow upstream acceptance; reconcile by transaction hash. Use the
[Core execution-safety contract](/api/supported-methods) and the separate
[Cloud workload contract](/cloud/rpc-behavior) before choosing a retry policy.

**Non-Retryable Errors:**
- `-32700` Parse Error (fix request format)
- `-32600` Invalid Request (fix request structure)
- `-32601` Method Not Found (use correct method/transport)
- `-32602` Invalid Params (fix parameters)

### Circuit Breaker Awareness

When all providers fail with circuit breakers open, consider:
- Switching to a different chain if available
- Implementing client-side caching for recent data
- Showing user-friendly error messages
- Monitoring circuit breaker state via observability metadata

### Error Logging

Always log the `data` field for debugging:

```javascript
if (response.error) {
  console.error('RPC Error:', {
    code: response.error.code,
    message: response.error.message,
    context: response.error.data,
    request_id: response.error.data?.request_id
  });
}
```
