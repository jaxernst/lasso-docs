---
title: Profiles and reload
description: Give each app or environment its own providers and routing settings, and control whether profiles share upstream connections.
---

Profiles define chains, providers, and routing policy. They are configuration scopes, not client authentication boundaries. RPC Core has no built-in incoming client quotas; `rps_limit` controls the dashboard tester maximum and `burst_limit` is metadata.

## Shared upstreams

With `sharing_mode: auto`, identical upstreams can share physical connections, health observations, and transport circuit breakers across profiles. Separate profiles do not create separate upstream quota. A problem with the shared upstream may affect every referencing profile.

`sharing_mode: isolated` separates runtime state by profile. It does not increase the upstream account's quota or remove the provider's external limits.

Each profile retains its own provider membership and routing policy. Dashboard aggregate and region views describe different scopes; use a regional view when diagnosing a local failure.

## Multiple Profiles

Create separate profiles for different environments or use cases:

```text
config/profiles/
├── public.yml       # Included free public providers
├── production.yml   # Credentialed providers + own nodes
└── staging.yml      # Subset for testing
```

The dashboard lists configured profiles and links to this guide. To add a profile, create its YAML file in the profiles directory on each node and reload Lasso. For containers, follow [Docker deployment](/deployment/docker#custom-profiles-and-credentials). New profiles reuse connected WebSocket upstreams after reload.

## Reload

Validate, then reload the running release:

```bash
_build/prod/rel/lasso/bin/lasso check-config
_build/prod/rel/lasso/bin/lasso reload
```

From source, run the same commands in the IEx session started with `iex -S mix phx.server`:

```elixir
Lasso.Operator.Commands.check_config!()
Lasso.Operator.Commands.reload!()
```

`check-config` reads the profile files without changing the active routes, prints how many profiles it read, and warns about each `.yaml` file, which is never loaded because profile files end in `.yml`. Both commands exit nonzero on invalid configuration, and a rejected reload keeps the active configuration. A successful reload prints `:ok`; refresh the dashboard to see the change. Each node reads its own files, so distribute the same configuration to every node and reload each one.

## Routes

Access a profile at `/rpc/profile/:slug/:chain`:

```bash
# Included public profile
curl -X POST http://localhost:4000/rpc/ethereum ...

# Production profile
curl -X POST http://localhost:4000/rpc/profile/production/ethereum ...
```


See [Configuration](/configuration/overview) for validated fields and [Docker deployment](/deployment/docker) for host-mounted profiles.
